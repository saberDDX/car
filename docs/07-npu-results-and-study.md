# NPU 部署结果与重点复习

本页基于用户在 2026-11-20 回传的板端输出，完整抄录范围见
[本轮数据](../vision/reports/board-validation-2026-11-20.json)。云端没有连接板卡。
当前代码和脚本已经完成静态图、单线程摄像头及量化对比主线；用户已在后续独立预览确认实时画面及真人绿色检测框。
默认只显示人、汽车、摩托车、公交车、卡车；杯子、手机、椅子被过滤，第一版不扩展日常物品展示。

## 已测到什么

固定同一张 bus.jpg，按 FP→INT8→INT8→FP 执行，每轮配置预热 10 次、测量 100 次。
FP 指 Toolkit 默认 float16 的非量化构建，输入、类别筛选和后处理阈值保持一致。

| 指标 | 非量化 FP | INT8 |
| --- | ---: | ---: |
| rknn_run 均值 | 21.324 ms | 11.066 ms |
| processing 均值 | 46.566 ms | 18.104 ms |
| 模型文件大小 | 6,953,815 字节 | 4,990,923 字节 |
| 每轮最后一帧检测数 | 4 | 4 |

按日志中舍入后的汇总值，INT8 的 rknn_run 加速约 1.93 倍，processing 加速约 2.57 倍，
模型文件减小约 28.2%。这些比值范围不同，不能统称为端到端加速。
同类框按 IoU≥0.5 匹配，得到 4 对、双方未匹配数均为 0。
两份模型都不是人工标注；单张图不能证明“量化无损”或给出 mAP。
完整报告仍在板卡 `build/vision/comparisons/comparison-t60hkls5/report.json`，尚未传入云端。

摄像头完成 5 帧预热、900 帧测量，约 30.338 秒，完成检测吞吐约 29.666 FPS。
rknn_run 均值 10.545 ms，processing 均值 19.983 ms；采集等待/转换另计约 10.525 ms。
驱动 MONOTONIC/SOE 时间戳到后处理均值 54.298 ms，不能称为屏幕实际显示延迟。
测到 8 个缺失的 sequence 编号、0 次编号异常，原因未知，不能写“零丢帧”。
最后一帧为 0 个目标，不代表整段都无目标；后续独立预览已由用户确认真人绿框，
此后续视觉核对不等同于补齐之前 900 帧逐帧场景证据，也不附会成新一轮 3000 帧完整计时。
先前白帧的 100 帧结果保留为排障记录，不替代有效场景验收。

## 先看这五处代码

| 文件 | 亲自顺着调用看什么 |
| --- | --- |
| [convert_rknn.py](../scripts/npu/convert_rknn.py) | 检查 ONNX 输入/输出；设置 rk3576 和 /255；非量化与 PTQ 构建的区别；导出后记录摘要 |
| [detect_image.cpp](../vision/src/detect_image.cpp) | Runtime 动态库加载；Context 初始化；查询 Tensor；inputs_set→run→outputs_get；计时与资源释放 |
| [v4l2_capture.hpp](../vision/include/v4l2_capture.hpp) | S_FMT→REQBUFS→QUERYBUF→mmap→QBUF→STREAMON→DQBUF；转换成自有内存后再 QBUF；析构清理 |
| [yolo.hpp](../vision/include/yolo.hpp) | 三尺度检测头解码、置信度筛选、类别筛选、同类别 NMS；回到主程序看去 letterbox 坐标映射 |
| [compare_models.py](../scripts/npu/compare_models.py) | 同图同参数、预热、ABBA 顺序、失败日志保留、耗时和框匹配统计 |

Runtime、Context、Outputs 是资源管理包装，不是自行实现推理引擎。
它们的析构分别负责 dlclose、rknn_destroy、rknn_outputs_release；对象寿命必须让输出先释放、上下文后销毁、动态库最后关闭。
当前使用 want_float=1 获取浮点输出，反量化由 Runtime 完成，不能说自己实现了零拷贝 INT8 后处理。

## 与面试题的对应范围

| 题号 | 本项目实际对应内容 | 尚未亲手验证的边界 |
| --- | --- | --- |
| 1、5、6、7 | 固定模型导出 ONNX、图检查、PyTorch/ONNX 输出对照 | 没有编写 ONNX 推理引擎，也没有覆盖全部导出失败情形 |
| 2、12～16 | PTQ 校准、FP/INT8 部署、同图结果和性能对比 | 20 张示例校准图；未做标注集 mAP、QAT 或完整精度恢复 |
| 3、18、19、25～28 | RKNN API 生命周期、分段计时、预热、均值/P50/P95、吞吐与帧年龄 | 未证明全部算子硬件归属，未完成硬件性能计数器分析 |
| 4、20～24 | 文件大小与耗时对比；识别输出获取、采集等待等成本 | 不以参数量推断速度；没有实现剪枝、零拷贝或验证 CPU 回退 |
| 8～11、17 | 可结合转换日志学习图优化、融合、逐层误差 | TensorRT/NCNN/MNN 和逐层量化定位没有本项目实操证据 |

优先能独立解释一次推理、MMAP 缓冲区所有权、RAII、预处理一致性和三类计时。
继承、多态、复杂模板、多线程、DMA-BUF 与新硬件暂不补入第一版，先把现有实现讲清楚。

## 阶段性简历表述

可先写：“基于 RK3576 完成 YOLOv5n 的 ONNX→RKNN 部署及 C++ 推理程序，
实现 V4L2 MMAP 摄像头接入、检测后处理与分段性能统计；完成非量化与 INT8 同图对比，
INT8 的 rknn_run 均值由约 21.32 ms 降至 11.07 ms，模型文件减小约 28%。”

实现主要由助手协助完成；使用这段表述前，应亲自编译、修改关键逻辑并能解释其作用。
可补充“通过 USB 摄像头实时预览验证真人检测框”；真实车辆摄像头验收尚未回传。
长时无泄漏、零丢帧、零拷贝、多线程优化、QAT、驱动自研 NPU 均不能由当前结果推出。
