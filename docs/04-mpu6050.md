# 第四阶段：MPU6050 与 I2C

GPIO 按键驱动和 K1 打开 Qt 实时摄像头已经完成板卡功能验收。本阶段先打通 MPU6050 的寄存器访问和数据读取，再做简单显示。DHT11 和语音大模型继续延期。

## 先核对硬件与总线

需要模块型号或板上标识、全部引脚名称，以及现有接线信息，以确定供电、SDA/SCL、AD0 地址选择及是否需要 INT。用户尚未提供这些信息，不先指定供电接线。

优先检查官方排针表的 I2C7 M1：物理 3 脚 GPIO3_A1 为 SDA，物理 5 脚 GPIO3_A0 为 SCL，与按键使用的物理 7 脚 GPIO4_A6 分开。厂商 `rk3576-lubancat-i2c7-m1-overlay.dts` 将 i2c7 的 pinctrl 设为 `i2c7m1_xfer`；该组源码为 bank 3、offset 0/1、mux 11。运行设备树是否仍禁用该控制器、针脚是否空闲，需要板卡预检。

在板卡终端运行：

```sh
cd ~/car-driver-dev && git -c http.version=HTTP/1.1 pull --ff-only && sh scripts/prepare-mpu6050.sh
```

此命令读取内核配置、I2C7 符号与状态、现有 I2C adapter 和启动 overlay 配置，检查两根针脚的 pinmux 占用。不扫描 I2C 地址，不访问 MPU6050，不修改启动配置或加载新驱动。必要时挂载 debugfs 供占用检查。若 I2C7 已启用或针脚被占用，停止后根据输出判断，保留已有外设的配置。

## 后续实现与验收

1. 确定接线和 7 位 I2C 地址；MPU6050 的 AD0 决定 0x68 或 0x69。不能把含 R/W 位的 8 位地址填入设备树。
2. 实现自己的 I2C client 驱动，匹配自定义 compatible，检查适配器能力和 WHO_AM_I，再进行芯片唤醒及量程配置。
3. 读取三轴加速度、三轴角速度和芯片内部温度，正确处理寄存器的大端数据、有符号 16 位数及量程换算。
4. 先用命令行验证静置时加速度合量约 1g、倾斜时各轴变化、转动时角速度变化，再接少量 Qt 显示。

驱动具体用户接口在确认板卡配置后确定。初期不需要做复杂姿态融合或追求精确车辆运动估计；静态/准静态倾角可以由重力分量估计，运动中的线性加速度会影响结果。芯片内部温度不作为环境温度测量。

本阶段知识点集中在 I2C 控制器/适配器与 client 的关系、设备树枚举、驱动匹配、寄存器读写与重复起始、ACK/NACK、地址与端序、错误处理和资源生命周期。

## 验证状态

厂商源码和用户提供的排针表已核对；云端已检查脚本语法及两针脚占用判断的错误路径。模块引脚、板卡 I2C7 状态、接线、芯片通信和新驱动仍待验证。
